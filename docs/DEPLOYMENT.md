# Deploying to AWS (Mumbai, ap-south-1)

Everything runs in one AWS account and region. Terraform in
[`infrastructure/terraform`](../infrastructure/terraform) creates the whole stack. After that,
every push to `main` that passes CI is deployed by
[`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml).

```
                 Route 53  yourplatform.in, *.yourplatform.in
                    │
            WAF ─ ALB (HTTPS, ACM certificate)
              │                    │
   *.domain, domain         api.domain (Razorpay webhooks)
              │                    │
        ECS Fargate: web ──► ECS Fargate: api ──► RDS PostgreSQL 17 (private)
        (Next.js)  api.lms.internal  (NestJS)  ──► S3 (course files, certificates)
                                               ──► SES (email), Razorpay (via NAT)
```

- **Private by default.** Containers and the database sit in private subnets. Only the load
  balancer is public. The database accepts connections only from the API, and only over TLS.
- **Secrets** are generated by Terraform and kept in Secrets Manager. ECS injects them into the
  containers at start. They never appear in GitHub or in the task definitions.
- **No AWS keys in GitHub.** The deploy job assumes an IAM role through GitHub's OIDC. The role
  only trusts this repository's `production` environment.
- **Logs** go to CloudWatch and are kept for 180 days (CERT-In asks for 180 days). Alarms email you.

## 1. One-time prerequisites

1. **An AWS account.** Turn on MFA for the root user, and create an admin user or SSO login for
   yourself. Run Terraform with that login, never with root keys.
2. **A domain in Route 53.** Create a public hosted zone for your domain. If you bought the
   domain elsewhere (GoDaddy, Hostinger, …), set the four Route 53 name servers at your registrar.
   Wait until `dig NS yourplatform.in` shows them.
3. **A bucket for Terraform state.** Create it once and keep versioning on:
   ```bash
   aws s3api create-bucket --bucket <your-tf-state-bucket> --region ap-south-1 \
     --create-bucket-configuration LocationConstraint=ap-south-1
   aws s3api put-bucket-versioning --bucket <your-tf-state-bucket> --versioning-configuration Status=Enabled
   ```
4. Install Terraform 1.13+ and the AWS CLI v2.

## 2. Create the infrastructure

```bash
cd infrastructure/terraform
cp terraform.tfvars.example terraform.tfvars     # set domain_name, github_repository, alarm_email
terraform init -backend-config="bucket=<your-tf-state-bucket>"
terraform plan -out tf.plan
terraform apply tf.plan
```

The first apply takes about 15–20 minutes, mostly for RDS and certificate validation. The ECS
services start but stay unhealthy until the first deploy pushes images. That is expected.

Then:

1. **Confirm the alarm email.** AWS sends a confirmation link to `alarm_email`.
2. **Add your Razorpay keys.** In the Secrets Manager console, open the secret named by the
   `razorpay_secret_name` output and replace the three placeholder values. Use test-mode keys
   first. Terraform won't overwrite your edits.
3. **Request SES production access.** In the SES console (ap-south-1), go to *Account
   dashboard* → *Request production access*. Until AWS approves it, email goes only to
   addresses you have verified in SES. The domain, DKIM, SPF (`mail.<domain>`) and DMARC records
   are already in place.
4. **Set up GitHub:**
   - *Settings → Environments → New environment* `production`. Under *Deployment branches*,
     choose *Selected branches* and add `main`. Optionally add yourself as a required reviewer,
     so every deploy waits for your click.
   - *Settings → Secrets and variables → Actions → Variables*: add `AWS_DEPLOY_ROLE_ARN` with
     the `deploy_role_arn` output.
5. **Deploy.** Merge to `main`, or run the *Deploy* workflow by hand (*Actions → Deploy → Run
   workflow*). The pipeline:
   1. builds both images and pushes them to ECR, tagged with the commit;
   2. runs the database migration task (Prisma migrations, row-level security, database role
      passwords). If it fails, nothing is deployed;
   3. rolls out the API, then the web app. New tasks must pass health checks before old ones
      stop. ECS rolls back a deployment that can't get healthy, and the job then fails.
6. **Point Razorpay's webhook** at `https://api.<domain>/webhooks/razorpay`. Use the webhook
   secret from step 2 and the events listed in the [README](../README.md#razorpay-setup).
7. **Create your platform admin.** Run a one-off task from the API image. Use a temporary
   password: it is visible in the task's details in the ECS console.
   ```bash
   CLUSTER=$(terraform output -raw cluster)
   SUBNETS=$(terraform output -json private_subnets | jq -r 'join(",")')
   SG=$(terraform output -raw api_security_group)
   aws ecs run-task --cluster "$CLUSTER" --launch-type FARGATE --task-definition lms-production-api \
     --network-configuration "awsvpcConfiguration={subnets=[$SUBNETS],securityGroups=[$SG],assignPublicIp=DISABLED}" \
     --overrides '{"containerOverrides":[{"name":"api","command":["node","dist/scripts/create-platform-admin.js"],
       "environment":[{"name":"PLATFORM_ADMIN_EMAIL","value":"you@yourplatform.in"},
                      {"name":"PLATFORM_ADMIN_PASSWORD","value":"temporary-password-123"}]}]}'
   ```
   Then sign in at `https://<domain>/login`, change the password with *Forgot password*, and
   turn on two-factor authentication.
8. **Turn on malware scanning for uploads.** In GuardDuty → *Malware Protection for S3*, enable
   it for the bucket in the `files_bucket` output, and tag scanned objects.
9. **Create your plans** in the platform console. Then sign up a test institute end to end
   with Razorpay test mode before you switch to live keys.

## 3. Everyday operations

| Task | How |
|---|---|
| Deploy | Merge to `main`. Watch *Actions → Deploy*. |
| Roll back | *Actions → Deploy → Run workflow* from an older commit, or choose the previous task definition revision in the ECS console (*Update service*). Migrations don't roll back, so keep each one backward-compatible with the previous release: add first, remove later. |
| Logs | CloudWatch → Log groups → `/ecs/lms-production/api` (also `web`, `migrate`). |
| Scale | Change `api_desired_count` / `web_desired_count` (or CPU and memory) in `terraform.tfvars`, then `terraform apply`. |
| Rotate Razorpay keys | Edit the Razorpay secret, then *Update service → Force new deployment* for `api`. |
| Database shell | No public access, by design. Use a one-off ECS task, or add a bastion with SSM Session Manager when you need one. |
| Upgrade Postgres | Change `engine_version` in `rds.tf` in a maintenance window, after taking a snapshot. |

Terraform ignores the task definition that each service runs, so `terraform apply` doesn't
undo deploys. Changing environment variables in `ecs.tf` creates a new task definition
revision. The next deploy copies that latest revision, so new variables take effect on the next
deploy.

## 4. Backups and restore

- RDS takes automated daily backups and keeps 14 days, with point-in-time restore. Deletion
  protection is on, and a final snapshot is taken if the database is ever deleted.
- S3 versioning keeps overwritten or deleted files for 90 days.
- **Practise a restore before launch, then once a quarter:** RDS → *Restore to point in time* →
  new instance → run a one-off task against it, or compare row counts, then delete it. Write
  down how long it took. That is your real recovery time.

## 5. Rough monthly cost

On-demand prices for ap-south-1 with the defaults (two tasks each for web and API, single-AZ
database). Check the [AWS Pricing Calculator](https://calculator.aws/) for current figures.

| Item | ≈ USD / month |
|---|---|
| Fargate: 4 tasks × 0.5 vCPU / 1 GB | 75 |
| NAT gateway (1) + data | 45 |
| Load balancer | 25 |
| RDS db.t4g.small, 20 GB gp3, backups | 45 |
| WAF (web ACL + 4 rules + requests) | 10 |
| CloudWatch logs, Container Insights, alarms | 15 |
| Secrets Manager, Route 53, ECR, SES, S3 (light use) | 10 |
| **Total** | **≈ 225 (₹19,000)** |

- **To save money early:** run one task each for web and API (about −$38) and turn off
  Container Insights (about −$10).
- **When you grow:** set `db_multi_az = true` (database cost roughly doubles) before you have
  many paying institutes.
- Data transfer and S3 storage grow with video uploads. Keep an eye on them in Cost Explorer,
  and set an AWS Budget alert.

## 6. Notes

- **Image sizes:** the API image is about 1 GB and the web image about 400 MB. The API image is
  mostly the Prisma engines and the AWS SDK. Pulls happen inside AWS, so this mainly affects
  deploy time.
- **Database roles:** the API connects as `lms_app` (row-level security per institute) and as
  `lms_platform` (platform screens and webhooks). Neither role owns tables or bypasses RLS. Only
  the migration task uses the master user.
- **Before taking real student data:** have the DPDP Act obligations reviewed (see
  [ARCHITECTURE.md](ARCHITECTURE.md#6-security-baseline)). Also publish a privacy policy and
  terms on the platform site.
